# 项目扩展规范（admin-ui-spec 附录 A）

本文件承接「只在 iot-admin 成立」的界面约定：业务词、状态枚举与颜色映射、操作名、页面清单，
以及明确不做的条款。共通的交互/布局条款以 admin-ui-spec 为准，本文件只写**项目特有**部分，
冲突时业务词与枚举以本文件为准。

> 维护约定：新增实体、只读页、状态枚举或操作名时**同一次提交内**更新本文件；
> 文案以 `internal/admin/*.go` 的 `entityLabels` 与各 `*Options` 为准，前端不另起名字。

## 1. 术语表

界面用词与代码标识的对照。**一个概念只有一个中文名**，不在不同页面换说法。

| 中文名 | 代码/接口标识 | 含义 |
|---|---|---|
| 数据域 | `data-domains` / `data_domain` | 业务域（当前只有 `energy`） |
| 终端类型 | `device-types` / `device_type` | 一类终端的定义载体（当前只有 `meter`） |
| 终端属性 | `thing-model-properties` / `thing_model_property` | 终端类型下声明的数据项定义。**界面只说「终端属性」**；代码标识保留 `thing_model_property`，URL 段仍是 `thing-model-properties` |
| 终端 | `terminals` / `terminal` | 一台被采集的设备，归属于某网关 |
| 质量规则 | `quality-rules` / `quality_rule` | 行级质量判定规则 |
| 快照计划 | `snapshot-slots` / `snapshot_slot_config` | 快照配置页的导航实体（标题仍是「快照计划」；页面三段式：六档配置 / 存储与保留 / 绑定）。老链接 `/ui/snapshot-plans` 会 replace 重定向到 `/ui/snapshot-slots` |
| 六档配置 | `snapshot-slots` / `snapshot_slot_config` | **六行固定**（秒/分/时/日/月/年），全局唯一；每行「启用 + 步长」，保存后全站生效。档位不可增删。步长下拉优先读 `_meta.enums.<档>_step`，未下发时用前端兜底白名单 |
| 绑定 | `snapshot-bindings` / `snapshot_binding` | **单目标多字段**：一条 = 一个目标（终端类型级，或终端实例级）+ 一个数据项数组（`item_codes`，jsonb）。一个目标只能有一条绑定，多字段在该行内原子替换。只有绑定过的数据项才会产生快照；增长由绑定条数 × 每条字段数 × 全局启用档位数决定，与终端总数无关 |
| 段起点 | `segment_start` | 一条快照所归属的自然时间段起点（+08:00 对齐），也是分区键与保留期裁剪依据 |
| 保留期 | `snapshot-settings` / `retention_days` | **表级**配置（粗/分/秒三行固定），空 = 永久保留；不是档位级配置 |
| 网关 | `gateway_id` | **边缘采集网关**：物理/边缘侧负责采集并上报的设备。专指这一类硬件，不指 Broker、不指通道；**不要**与「终端」混用 |
| 通道 | — | 收数据的**传输方式**：HTTP 通道 / MQTT 通道。**不要**用它指代来源 |
| Broker | BroMQ | 消息代理（Broker，本实现为 BroMQ）。基础设施角色，**界面上不出现** |
| 接入源 | `gateway_id` | 数据来自谁。当前等同边缘采集网关；**不要**与「通道」混用 |
| 采集时间 | `value_time` / `collectedAt` | 设备侧采样时刻 |
| 最新值 | `latest-values` | 每（终端, 数据项）一行，最近一次写入 |
| 异常事件 | `exception-events` | 事件型异常（计数表，按小时聚合） |
| 数据项 | `item_code` | 终端属性里的一个数据项编码 |
| 补录 | `msgType=2` | 补传历史数据（只作来源标记，不影响落库路径） |

**接入层命名的三条规则**：

- 「网关」**专指边缘采集网关**，不指 Broker、不指通道。
- **Broker 是角色、BroMQ 是实现**；换实现只改实现名（文档与示例配置里的 `BroMQ` 字样），
  角色名「Broker」不变。
- 将来引入**非网关的接入源**时，不要复用 `gateway_id` 填假值——那会让「终端/网关/数据域」
  三方一致校验静默失效。届时再评估是泛化该字段还是新增字段。

**已下线、不要再用**：`异常区间` / `exception-intervals` / `gateway_disconnected` / `item_silent` /
`auth_failed`（状态型异常整套已移除）、`快照变更查询` 的**写入侧留痕**（`snapshot_cell_history`）、
`小时暂存` / `小时快照` / `结算窗口`（小时级历史与结算窗口整条链路已下线，迁移 `0009`）。

## 2. 状态枚举与颜色映射

### 2.1 颜色通道

状态色只有五档语义 `tone`，取值与令牌一一对应（颜色只来自 `web/src/styles/tokens.css`，
组件里**不得**出现颜色字面量）：

| tone | 背景令牌 | 文字令牌 | 语义 |
|---|---|---|---|
| `success` / `positive` | `--color-positive-bg` | `--color-positive-text` | 正常、启用、成功 |
| `warning` | `--color-warning-bg` | `--color-warning-text` | 需关注但不阻断 |
| `danger` / `negative` | `--color-negative-bg` | `--color-negative-text` | 失败、停用、拒收 |
| `info` | `--color-info-weak` | `--color-info` | 中性说明/链接型状态 |
| `neutral` | `--color-neutral-bg` | `--color-neutral-text` | 无状态、空值 |

规则：**颜色只是辅助**，状态标签必须同时有文字（§17）；不得用颜色单独表达状态；
不得为状态新增第六档 tone。

### 2.2 枚举清单（权威来源：`internal/admin/fields.go` 的 `*Options`）

| 枚举 | 取值 → 文案（tone） |
|---|---|
| 启用状态 `enabled` | `true`→启用(success)、`false`→停用(danger) |
| 布尔值 `boolean` | `true`→是(success)、`false`→否(neutral) |
| 值类型 `value_type` | `number`→数值、`string`→文本、`bool`→布尔（均 neutral） |
| 规则类型 `rule_type` | `range`→范围、`enum`→枚举、`precision`→精度、`unit_whitelist`→单位白名单、`not_null`→非空（均 neutral） |
| 质量位 `quality` | `0`→正常(neutral)；`1`越界 / `2`规则命中 / `4`单位闭集外 / `3,5,6,7` 为组合（均 warning） |
| 事件型异常 `error_type` | `protocol_error`→协议错误(danger)、`msg_incomplete`→消息不完整(warning)、`clean_failed`→清洗失败(warning)、`cache_write_failed`→写入失败(danger)、`mqtt_publish_failed`→发布失败(danger)、`quality_violation`→质量违规(warning)、`terminal_unknown`→终端未注册(danger)、`snapshot_write_failed`→快照写入失败(danger)、`snapshot_late_dropped`→快照迟到丢弃(warning) |

> `snapshot_late_dropped` 的语义：某一档的采集时间超过该档容忍窗口（段结束 + 15 分钟）后被丢弃；
> 其它档仍照常写，所以看到这条不代表整条消息失败。
>
> **`snapshot_write_failed` 与已删除的 `snapshot_failed` 不是一回事**：后者是旧「结算任务失败」（小时结算链路，已随 `0009` 下线删除）；前者是六档快照（秒/分/时/日/月/年）写库失败，由 `internal/snapshot` 上报。看到日志里这两个词的任何一个，先看迁移版本再下结论。

> 注：`terminal_unknown`（终端未注册）在闭集里有定义，但后台筛选下拉当前**未**提供该项
> ——留作已知缺口，补齐时同步本表。

### 2.3 上报应答的逐终端状态（对外契约，见 `internal/ingest/pipeline.go`）

| 情形 | `accepted` | `reason` | 其他 |
|---|---|---|---|
| 全部项成功 | `true` | — | `written` > 0 |
| 部分项失败 | `true` | — | `failedCount` + `items[]` |
| 全部项失败 | `false` | `all_items_failed` | `items[]` 列全部失败项 |
| 结构性拒收 | `false` | `msg_incomplete` / `protocol_error` / `terminal_unknown` 等 | `missingCodes` 可能非空 |
| 平台故障 | `false` | `internal_error` | HTTP 整包 503 |

## 4. 页面清单

导航由 `GET /admin/v1/_meta` 的 `entities` 驱动，前端不硬编码实体名。当前共 **5 个导航实体页 + 1 个详情页 + 2 个只读页（最新值、快照）+ 1 个异常页**。

> 属性（`thing-model-properties`）不再是导航实体：`_meta.entities` 只有 4 项，属性改为「终端类型详情页」内的子列表。
> 它的字段元数据改由 `_meta.subresources` 下发（形状与 `entities[]` 相同，只装「可 CRUD 不可导航」的实体），CRUD 接口 `/admin/v1/thing-model-properties*` 全部保留。

### 4.1 实体页（可增删改查）

| 页面 | 路由 | 主要字段 |
|---|---|---|
| 数据域 | `/ui/data-domains` | 编码、名称 |
| 终端类型 | `/ui/device-types` | 编码、名称、数据域（关联） |
| 终端 | `/ui/terminals` | 终端 ID、终端类型（关联）、网关 ID、名称、状态 |
| 质量规则 | `/ui/quality-rules` | 终端、数据项、规则类型、阈值等 |
| 快照计划 | `/ui/snapshot-slots`（老链接 `/ui/snapshot-plans` 自动重定向） | 三段式（自上而下）：**六档配置**（六行固定，启用 + 步长，保存即全站生效，无新增档位入口）→ **存储与保留**（表级三行固定，不可增删）→ **绑定列表**（作用域 / 目标 / 字段数 / 创建时间 / 操作：编辑、删除）。绑定用专用表单（新增与编辑共用）：作用域 → 目标（类型远程下拉 / 终端远程搜索）→ 字段多选（候选来自目标类型的终端属性，可搜索、支持全选/反选、已选项标签可移除）；已选 0 个字段时保存禁用并说明原因；编辑态顶部提示「修改只影响后续写入，已产生的快照不变」 |

### 4.2 终端类型详情页（子资源）

| 页面 | 路由 | 内容 |
|---|---|---|
| 终端类型详情 | `/ui/device-types/:id` | 顶部摘要（编码、名称、归属数据域，可编辑）；主体是该类型下的**终端属性**列表（`type_id` 固定过滤、不可从筛选区改掉）；右上「新建属性」的 `type_id` 预填并锁定 |

### 4.3 只读页（仅查询，无写入口）

| 页面 | 路由 | 分页方式 | 说明 |
|---|---|---|---|
| 最新值 | `/ui/readonly/latest-values` | offset | 每（终端, 数据项）一行，保留当前状态 |
| 快照 | `/ui/readonly/snapshot-coarse`（`snapshot-minute` / `snapshot-second` 由页面内切换） | cursor | 六档自然时间快照；**一个页面 + 三个存储**（粗表 / 分表 / 秒表），存储切换写在 URL 路径里，刷新/分享可复原。粗表支持按**档位**（时/日/月/年）筛选。游标分页，不显示总数 |
| 异常事件 | `/ui/exceptions/events` | offset | 事件型异常计数 |

> 快照页的「加载更多」是**换批**而不是累加（每批由后端 `limit` 决定），且永远不显示总数：
> 分区表上 `count(*)` 会随分区数变慢，这是设计取舍；空态也不会出现「共 N 条」。
> 已不存在「小时暂存」「旧小时快照」页——小时级历史整条链路随迁移 `0009` 下线；
> 也不存在「异常区间」页——状态型异常整套下线（迁移 `0008`）。

## 5. 已知豁免（明确不做）

以下条款在本项目**不适用或不实施**，理由如下；如需改变，走新的需求，不在整改里顺手加。

| 条款 | 不做的内容 | 理由 |
|---|---|---|
| §5.2 | 列可见性与导出 | 列由 `_meta` 的 `visible` 固定下发，用户级列偏好需要持久化存储与后端支持；导出需要服务端异步任务与结果保留期，属独立能力。当前页面只有 5–10 列，横向滚动已可覆盖。 |
| §13.3 | 删除终端类型时不列出「将连带删除 N 个属性」 | 属性是终端类型的**子资源**，不是独立对象；确认文案保持极简（「删除 {名称}」）。这是有意为之，不是遗漏——若将来属性可以被别的类型共享，再补数量与二次确认。 |
| §9 | 批量选择与批量操作（L1/L2/L3 全豁免） | 后台 5 个治理对象的操作是低频单条编辑；批量删除/批量启用属高风险动作，需要服务端按条件执行 + 二次确认 + 部分失败重试，成本与收益不匹配。**注意**：本次豁免的是「批量」，不是「范围声明」——列表的分页/筛选范围文案仍须准确。 |
| §3.1 顶栏四项 | 全局搜索、主题切换、用户菜单 | 项目无鉴权（`AllowAll`，仅监听 127.0.0.1），没有「用户」概念；不做 dark mode 是既定决策（`tokens.css` 只有一套浅色令牌）。顶栏只保留页面标题与主操作。 |
| §3.2 二级导航 | 侧栏多级展开 | 导航按「实体 / 数据 / 异常」三组扁平排列，层级不超过一层。 |

## 5.4 字号 / 圆角词汇（只有一套类名）

| 需要 | 用这个类 | 实际值 |
|---|---|---|
| 最小字号（标签、元信息） | `text-sm` | 12px / 行高 18px |
| 正文 | `text-base` | 14px / 行高 22px |
| 小节标题 | `text-lg` | 16px / 行高 24px |
| 页面标题 | `text-xl` | 20px / 行高 28px |
| 导航（无 Tailwind 对应名） | `text-nav` | 11px |
| 控件圆角 | `rounded-sm` | 6px |
| 卡片圆角 | `rounded-md` | 10px |

**警告：这里的 `sm/base` 与 Tailwind 默认刻度不同**（默认 sm=14px、base=16px）。
本项目把 `--text-sm` 映射到 12px、`--text-base` 映射到 14px——**别按记忆写，改字号先查这张表**。

项目语义别名（`text-meta` / `text-body` / `text-section` / `text-page` / `rounded-control` /
`rounded-card`）已删除，`web/src/styles/style-rules.test.ts` 有守卫，出现即红。

**为什么别名必须彻底删掉**：`cn()` 用 tailwind-merge 合并类名，它不认识项目自定义的
`text-meta` / `text-body`，会把它们当成「文字颜色」与后写的 `text-text` / `text-muted` 判为冲突并**静默丢弃**。
结果这些类在 `text-xxx` 组合里从未生效（表头实际是继承来的 14px，而非声明的 12px）。
换成 Tailwind 名之后类才真正参与合并——这也是本次改名唯一带来视觉变化的来源。

## 5.5 表格列宽与对齐

- **列宽默认由字段类型推导**（后端 `widthForType`）：id 120 / boolean 90 / enum 120 / number 110 /
  datetime 170 / text 200 / relation 180；json 与未知类型不推导，交给 `widthStrategy` 的 flex。
  字段可在 `FieldMeta.Width` 里**显式覆写**，覆写优先。
- 推导结论由 `_meta` 的 `width` 下发，**前端只消费、不按类型重算**；未下发的类型回落 `widthStrategy` 的 CSS 类。
- `widthStrategy` 仍是契约字段，语义是"布局是固定/最小/弹性"，与具体像素值解耦。
- 表格**不再有独立卡片外壳**，直接贴在内容卡片内（避免卡片套卡片）；sticky 投影**只在发生横向滚动时出现**，不滚动时不可见。
- **数字列**右对齐 + `tabular-nums`（表头同步右对齐）；枚举/布尔/时间仍左对齐。
- 完整值提示由**表格级单一受控 Tooltip** 驱动（单元格只输出 `data-full`），只在内容真的被截断
  （`scrollWidth > clientWidth`）时出现，300ms 延迟，触屏点击不触发；键盘 focus 不触发（理由见 §5.6）。

## 5.6 表格完整值的可访问性限制

截断单元格的完整值**只对指针设备可见**（hover 300ms 出提示）。键盘与读屏用户依赖
DOM 里的完整文本与详情页，**不为每格加 `tabIndex`**——大表会产生成百上千个 tab 停留点，
反而把键盘用户困在表格里。这是有意为之，不是遗漏。

## 5.7 配色主题

三套配色，只换「皮肤」，不换语义：

| 主题 | `data-theme` | 用途 | 主色 |
|---|---|---|---|
| 深青（默认） | `teal` | 默认外观，工业监控场景的低饱和底色 | `#0F766E` |
| 电蓝 | `blue` | 偏仪表盘/演示，蓝色主色更接近常见后台 | `#2563EB` |
| 石墨 | `graphite` | 中性灰黑，弱化装饰、强调内容 | `#1F2937` |

约定：

1. **切换位置**：顶栏右侧、页面操作按钮左边的分段控件（`深青 / 电蓝 / 石墨`），点击即时生效、**不刷新**。
2. **持久化**：`localStorage['iot-theme']`，合法值只有 `teal` / `blue` / `graphite`；缺失或非法一律回落到 `teal`。
   首帧在 `createRoot().render()` 之前同步写入 `document.documentElement.dataset.theme`，避免闪一次默认主题。
3. **主题只覆盖 14 个令牌**：`bg / surface / surface-2 / border-subtle / border / border-strong / text / muted / faint / primary / primary-hover / primary-weak / on-primary / shadow-sticky`。
4. **语义色与图表色不随主题变**：成功/警告/危险/信息、`--chart-1..8`、`--media-*`、`--scale-1..10` 三套完全一致——红永远是危险，琥珀永远是电。
   组件里不允许出现颜色字面量，主题色只能写在 `styles/tokens.css`。
5. **石墨的链接与导航选中项带下划线**：石墨主色（`#1F2937`）接近正文色，仅靠颜色无法表达可点性，因此 `[data-theme='graphite']` 下链接与 `[aria-current='page']` 统一 `text-decoration: underline`；其它主题不变。
6. **focus ring 双层**：外圈主色 2px + 内圈 surface 2px（`outline-offset: 2px`），深色主色下也分得清。

## 6. 已知行为（不是缺陷，不要"修"）

| 行为 | 触发条件 | 为什么这样是对的 |
|---|---|---|
| 首屏骨架行数可能与回包行数不一致，页面会长高一次 | 首次进入某列表页，且「每页条数」> 10，且回包行数 > 10 | 首屏之前没有任何可参考的行数，「猜 10 行」是唯一合理默认。进入过一次后，骨架已改为 `min(每页条数, 上一次实际行数)`，后续翻页不再跳变。**不要把它改成按每页条数画 50 行**——那会把「数据多时一次长高」换成「数据少时一次塌陷」，后者更刺眼（页脚上移、点击落空）。 |
| 保留期按「整月 / 整日 DROP 分区」执行，实际保留时间可能比设定值更长 | 配置了 `retention_days` 之后 | 分区表只能整块 DROP（粗表/分表按月、秒表按日），所以设定 30 天实际会到下一个整月/整日边界才清理。**不能改成按行删**：秒表写入率高，按行 DELETE 会产生大量死元组、autovacuum 追不上，最终拖垮写入路径。 |
| 快照配置页的保存模型是「分段批量」 | 编辑六档配置或保留期时 | 每个子块一个保存按钮，一次提交本块全部改动（逐行串行 PUT）；有未保存修改时子块标题旁显示「有未保存修改」、无改动时保存禁用；部分失败时成功的行清出草稿、失败的行保留并标红。**不要退回成逐行保存按钮**（旧版 9 个保存按钮已收敛为 2 个）。 |
| 六档快照的增长由「绑定条数 × 每条字段数 × 全局启用档位数」决定，不由终端总数决定 | 配置了快照计划之后 | 只有 `snapshot_binding` 里登记过的（类型级或实例级）数据项才会按**全局启用的档位**写入；没有绑定的数据项不产生任何快照行。容量评估请按「绑定条数 × 每条字段数 × 全局启用档位数」算，不要按终端数估算。 |
| 系统不保留小时级历史，只在最新值上保留当前状态 | 查看「最新值」页与异常事件页时 | 结算链路已下线（迁移 `0009` 删除 `hourly_snapshot` / `hourly_staging` / `settle_config`），历史数据不可追溯是产品决策，不是丢数据 bug；查询历史的需求走外部归档，不在后台恢复。 |
| 分页区同时出现「第 1–4 条，共 4 条」与「第 1 页」 | 所有 offset 分页页 | 前者是**范围**，后者是**页码控件**，不是同一信息重复。§16.1 要去重的是「表格说明 + 分页区都报总数」，已去掉表格说明里的数字。 |
